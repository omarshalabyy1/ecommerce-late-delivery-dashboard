## The 3 error kinds found (all generated by my scripts or `make_frames.py`)
1. **`syncGroup` at the root of 16 slicer visuals** (Year and State, 8 analysis pages): the schema allows it only inside `visual`. Root-level is "additional property not allowed". Source: `pipeline/build_pages.py`, `slicer()` / `write()`.
2. **Plain-string sort field in 3 table visuals** (`pg03Products` chart04, `pg07Sellers` chart04, `pg08DataTable` chart01): `"sortDefinition": {"sort": [{"field": "Revenue", ...}]}`. The schema needs a field object (`{"Measure": {...}}`). Source: `build_pages.py`, `table()` passes the sort name as a string where `chart()` expects a field.
3. **`$schema` URL that does not exist** on all 188 visuals (`visualContainer/2.14.0`, including the 104 `ff_*` frame visuals from `make_frames.py` and my 84) and an older page schema (`page/2.0.0`; Desktop's own first page used 2.1.0).

| 2 | String sort field in 3 tables | Hard schema violation (wrong type) on 3 pages |

Why only after Refresh: a likely reading is that Desktop loads the active page first and parses the other pages when the model changes after the first data load (calculated objects, then rebuild). That is inference, not observed.
